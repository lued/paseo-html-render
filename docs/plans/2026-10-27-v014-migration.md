## Goal

Make html-render run on Paseo `0.14.0-beta.1` using the session-open plugin API, and
fix the Android native ready timeout that the current `4b9e77a` mitigation does not
fix on the real phone. Keep `main` untouched; no push, tag, or npm publish.

## Decisions

1. **MCP at `agent.session_open`, not `defineAgentTool`.** `html_preview` returns a
   real PNG image content block (`server/adapter-source.ts:271-276`). 
   `AgentToolResult` has no image field and the daemon emits text only
   (`plugin-tools.ts:30-37`). Native tools would silently degrade the preview.
2. **New MCP server key: `html-render-v3`.** A 2.2.0 agent has `html-render`
   saved in its agent record. A 0.14 session-open contribution with the same name
   fails every open with `collides with agent saved configuration`. The plugin
   cannot see or remove that saved entry. The new key coexists; the old entry is a
   documented one-time cleanup. The marker prefix, data dir, tool names, and
   timeline kind stay unchanged.
3. **Keep the stdio adapter and bridge, but version the transport files.**
   Adapter `mcp-adapter-v3.mjs`, socket `bridge-v3.sock`, token `bridge-v3.token`.
   A legacy tombstone at `mcp-adapter-v1.mjs` stops an old saved agent from
   silently connecting to the new bridge with the old protocol. The token stops
   being persisted because injection is launch-only.
4. **Delete `agent.create` injection.** No saved MCP config is written by the
   plugin anymore. New agents, resumed agents, imports, and refreshes all derive
   the server from `session_open`.
5. **Per-agent targeting via labels.** Skip injection for agents labelled
   `html-render/disabled: "true"`; inject for every other interactive agent. This
   uses the new read-only `labels` field without changing default behavior.
6. **Native transport v2.** Add RNCWebView `onMessage` as the primary page→native
   channel with the existing fragment path as fallback. The fragment callbacks are
   the unproven hop; `messagingEnabled` is currently `false`, so the reliable
   channel is unused. Add stage diagnostics and keep a working report mounted when
   only the control channel fails.
7. **Turn collapse is a host behavior, not a plugin defect.** There is no opt-out.
   Keep the final-reply `[Open interactive report](...)` link (it survives the
   fold) and document that new installs default to collapsed turns. Do not claim
   the card is visible by default.
8. **Verify on slydio.** Back up `~/.paseo/config.json`, install
   `@getpaseo/cli@0.14.0-beta.1` with the existing nvm Node, restart the daemon,
   sync this branch, install the plugin from the worktree, and run the real-daemon
   checks there. The sly UI alone is not enough: the plugin executes in the daemon.

Frozen names and versions (from the repo scout):

- Package/adapter version `3.0.0`; `@getpaseo/plugin` `0.14.0-beta.1`.
- Host range `>=0.14.0-beta.1 <0.15.0` in `paseo-plugin.json` and the peer dep.
- MCP key `html-render-v3`; adapter `mcp-adapter-v3.mjs`; socket `bridge-v3.sock`;
  token `bridge-v3.token`; legacy tombstone `mcp-adapter-v1.mjs`.
- `check-package.mjs` requires adapter version == package version; keep
  `server/authority.ts`, `server/contribute.ts`, `server/tools.ts`,
  `shared/identity.ts` names.

Rejected alternatives:
- `defineAgentTool` for both tools — loses the PNG preview.
- HTTP MCP from the plugin — more surface for no functional gain in this pass.
- Keeping the `html-render` server name — fails every legacy agent open.
- Raising the ready deadline — hides the defect and fails the diagnostic gate.

## Acceptance checks

Local (must all pass):

- `npm run typecheck`
- `npm test`
- `npm run check:bundles`
- `npm run check:package`
- `npm run verify:e2e` with a real `0.14.0-beta.1` daemon
- No `agent.create` MCP injection remains (`rg 'before\\("agent.create"' server` empty).
- `paseo-plugin.json` and peer dependency require `>=0.14.0-beta.1 <0.15.0`.
- Package, adapter, and `check-package` all report `3.0.0`.
- The new agent's launch config contains `html-render-v3`; its saved agent
  record does not contain that server.
- A legacy agent created under 2.2.0 (saved `html-render`) opens successfully; the
  new server is present; the old entry does not fail the open; the old adapter is
  a tombstone rather than a live bridge client.
- `scripts/smoke-package.mjs` proves injection from the sanitized session-open log
  line, not from persisted `config.mcpServers`.
- `scripts/check-bundles.mjs` matches the 0.14 host compiler: client target
  `es2020`, server target `node20`, explicit SDK externals, no Node builtins in
  the client bundle, no private `client/host` import.
- `paseo plugin reload html-render` reaches an idle agent on its next prompt.
- `paseo plugin disable html-render` removes the tools on the next idle prompt.
- A history open does not spawn the adapter.
- An idle runtime release + resume re-injects the server.

Native (sly + phone, user participates):

- Cold start: ready ≤2 s; no error at t+10 s.
- Dwell 120 s: no error, controls still respond.
- Cold reopen ×2: same result, 2/2.
- Background/resume 30 s: re-handshake ≤2 s.
- Theme round-trip: palette changes ≤2 s, no theme-ack error.
- Links and image zoom work.
- If it fails, the error names the stage (no page messages / chunks without ready /
  probe unanswered) and logcat shows whether any callback URL contained
  `#paseo-p2n=`.
- A working report stays mounted behind a non-blocking banner on control-channel
  failure; Retry succeeds without an app restart.

Turn-collapse check:

- Under `collapseTurns`, the card is folded into the summary line; expanding the
  turn reveals it.
- The final-reply report link remains visible.
- No duplicate card after refresh or history rebuild.

## Risks

- Legacy saved server collision is real; the new name is the mitigation, and the
  old entry may still show a stale adapter until the agent is recreated.
- Turn collapse can hide the card on new installs; no plugin API can opt out.
- `onMessage` requires `messagingEnabled: true` and host support; the fragment
  fallback must remain.
- Upgrading slydio's daemon affects its running agents. Back up config, prefer an
  idle window, and keep the rollback command.
- The sol child may not receive Paseo delegation tools. If it cannot create
  workers, it must do the work itself and say so in its report.
